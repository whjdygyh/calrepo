# 泰国与天主教日历源调研 - 2026-07-22

## 目标

按两步判断泰国公共假日与天主教礼仪日历：

1. 先寻找可直接订阅、来源和再发布边界清楚的现成日历；
2. 未达到公开发布标准时，以权威规则为依据建设 CalRepo 自有源。

本报告的“可订阅”仅表示技术可用。它不等于数据已被 CalRepo 认证，也不等于允许镜像、重发布或改名为 CalRepo 数据。

## 泰国公共假日

### 已验证的外部候选

| 项目 | 结果 |
| --- | --- |
| 候选 | OfficeHolidays Thailand ICS |
| 订阅地址 | `https://www.officeholidays.com/ics-all/thailand` |
| 2026-07-22 技术复测 | HTTP 200；`text/calendar; charset=UTF-8`；51 个 `VEVENT` |
| 覆盖窗口 | 2026 年 26 项、2027 年 25 项 |
| 内容抽样 | 元旦、春节（地区性）、万佛节、宋干节、佛诞、王室庆典等 |
| 缓存提示 | `Cache-Control: private, max-age=14400`；未返回 ETag |
| 准入结论 | 可作为外部直订候选；不得镜像、代理、重命名或作为 CalRepo 自有数据发布 |

该站点不是泰国政府机构。其页面只把该地址作为消费者订阅服务提供，尚未取得明确的再分发许可；`robots.txt` 还明确禁止其 `/ics/` 路径被 chatgpt 抓取。因此，不能把该数据作为 CalRepo 自建源的底稿。

### Google 候选

Google 的 `en.thai#holiday@group.v.calendar.google.com` 已连续三次返回 HTTP 500 的 HTML 错误页，已排除。

### 自建可行性

泰国公共假日不宜用单一“万年算法”完整生成：部分佛教节期涉及泰阴历或官方公布日期，王室与政府特别假日也可能逐年调整。可行的自建边界是：

- 源名：`泰国官方公共假日`。
- 发布方式：按泰国政府正式年度公告逐年录入，不推断未经公告的临时补假。
- 数据模型：每条事件保留公告编号、发布机关、泰历/公历日期、是否全国适用、是否地区性、是否政府工作日、最近核验日期。
- 更新：每年公告发布后人工复核一次；遇临时特别假日再增量更新；订阅输出可每日构建，但不需每日改动内容。
- 验收：每年与官方公告逐项比对，并保留英文、泰文和中文显示名的来源记录。

在取得泰国政府公报或内阁正式公告的稳定来源前，此自建源保持 `待研究`，不得提前对外发布。

### 自建建议

建议建立的第一条自有天主教源是“通用罗马礼日历（General Roman Calendar）”，而不是笼统的“全球天主教日历”。

- 范围：采用通用罗马礼；不含教区、国家、修会和堂区专属庆日。
- 不覆盖：地方主保、地区法定圣日、教区纪念日、东方天主教礼仪、传统拉丁礼 1962 日历等。它们需独立成源。
- 规则：固定庆日、复活节计算、圣灰日、四旬期、圣周、五旬节及庆日优先级均以圣座规范和后续法令建模。
- 语言：先采用拉丁语/英语事实名称并建立中文译名审校表；不能把机器翻译直接作为礼仪名称发布。
- 版本：每年发布 `vYYYY.N`，保留规则版本、参考法令、生成器版本和跨年测试样本。
- 复核：每年一次常规复核；圣座礼仪与圣事部有新法令时立即复核；发布前与 Apache-2.0 开源引擎及至少一个正式主教团年历交叉比对。

## 当前决策

1. 泰国：保留 OfficeHolidays 外部直订候选，标记为“技术可用、许可未审计”；同时研究泰国官方年度公告以准备自建。
2. 天主教：不采用 Google 失败候选，不将梵蒂冈教宗活动日历当作通用日历；按通用罗马礼自建预案推进。
3. 两类自有源都必须先通过规则、权威引用、跨年度样本和许可记录的发布门槛，才可在 `calrepo.com` 发布 ICS。
